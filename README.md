# MCDiag Agent

Лёгкий плагин-агент телеметрии для серверов **Paper, Purpur, Leaf и других форков Paper 1.19.4+** (Java 17+). Собирает входы, выходы, смерти, SEVERE-ошибки, метрики (TPS, MSPT, online, entities) и **нагрузку от каждого плагина** и раз в 10 секунд асинхронно отправляет их батчем в MCDiag (`POST /api/v1/ingest`).

- Jar ≈ 90 KB, без зависимостей: только публичный Paper API, JSON собирается вручную.
- Память: буфер ограничен (по умолчанию 500 событий + 60 точек метрик + 10 минутных срезов профилировщика), в обычной работе меньше 150 KB.
- Влияние на TPS: в основном потоке выполняются только обработчики join/quit/death (хеш и одна строка), отметки начала и конца тика и подсчёт сущностей раз в 5 с. Сеть, метрики и профилировщик работают в других потоках.

## Установка

1. Скопируйте `MCDiag-Agent.jar` в `plugins/` и запустите сервер (или перезапустите, если он уже работал). Будет создан `plugins/MCDiag/config.yml`, при первом запуске в нём генерируется `uuid_salt`.
2. `backend_url` по умолчанию указывает на `https://mcdiag.rimworlda.ru/api/v1/ingest`. Меняйте его, только если панель работает на другом адресе (только `https://`).
3. Задайте токен **из консоли сервера**:
   ```
   diag token mcd_<serverId>_<uuid>
   ```
   Из чата команда запрещена: команды игроков пишутся в лог, и токен попал бы туда.

## Конфигурация

| Ключ | По умолчанию | Описание |
|---|---|---|
| `backend_url` | `https://mcdiag.rimworlda.ru/api/v1/ingest` | URL приёма, только HTTPS. При `http://` отправка не запускается |
| `server_token` | `""` | Токен сервера из панели. Нигде не логируется, в выводе маскируется как `mcd_****abcd` |
| `uuid_salt` | генерируется | Соль SHA-256 для UUID. Не меняйте после запуска |
| `batch_interval_sec` | `10` | Период отправки, 5–3600 |
| `max_buffer_size` | `500` | Лимит событий в памяти, 10–5000. Старые вытесняются |
| `max_batch_events` | `100` | Событий в одном запросе, 1–500 |
| `metrics_interval_sec` | `5` | Период метрик, 5–60 |
| `max_errors_per_minute` | `30` | Лимит ошибок в минуту, остальные отбрасываются |
| `collect.*` | `true` | Вкл./выкл. `joins`, `quits`, `deaths`, `errors`, `metrics` |
| `profiler.enabled` | `true` | Профилировщик плагинов |
| `profiler.interval_ms` | `20` | Интервал сэмплов внутри долгого тика, 10–200 мс. В обычное время сэмпл снимается в среднем раз в 50 мс |
| `profiler.spike_threshold_ms` | `100` | Тик дольше порога сохраняется как лаг-спайк, 50–10000 |
| `profiler.async` | `true` | Учитывать CPU асинхронных потоков плагинов |
| `profiler.spike_logs` | `true` | Прикладывать к спайку строки лога плагинов |
| `chat_log.allowed` | `true` | `false` полностью запрещает журнал чата и команд, что бы ни было включено в панели |
| `chat_log.hidden_commands` | `[]` | Дополнительные команды, у которых скрываются аргументы, например `[mypass]` |

## Команды

Право `mcdiag.admin` (по умолчанию у операторов).

| Команда | Действие |
|---|---|
| `/diag status` | Состояние отправки, маска токена, заполнение буфера, примерный объём буфера в KB, число отброшенных записей, результат последней отправки, снимков стека в секунду и их доля времени, собственный CPU профилировщика, heap JVM |
| `/diag plugins` | Топ плагинов по нагрузке на главный поток за последнюю полную минуту: мс на тик и доля |
| `/diag spikes` | Последние 10 лаг-спайков и кто занимал тик |
| `/diag token` | Показать маску токена |
| `diag token <value>` | Задать токен (только из консоли), сохранить в конфиг и применить |
| `/diag reload` | Перечитать `config.yml` и перезапустить таски |

## Что собирается

| Событие | Поля |
|---|---|
| `join` | `ts`, `playerHash`, `firstJoin`, `world` |
| `quit` | `ts`, `playerHash`, `sessionSec` (из `Player#getLastLogin`) |
| `death` | `ts`, `playerHash`, `cause` (DamageCause), `killerType` (`PLAYER` / тип моба / `NONE`), `world` |
| `error` | `ts`, `logger`, `message` (≤ 512), `trace` (≤ 36 строк / 6000 символов) |
| метрика | `ts` (кратно 5 с), `tps`, `mspt`, `online`, `entities` |
| срез профилировщика (раз в минуту) | время главного потока по плагинам и частям ядра, CPU асинхронных потоков плагинов, средний и максимальный тик, лаг-спайки, процессор / heap / GC JVM |
| список плагинов (при старте и изменениях) | имя, версия, включён ли |
| системный срез (раз в минуту) | CPU процесса и машины, память JVM и машины, время GC, потоки, занятость диска, аптайм |
| метрика (0.3.0+) | плюс загруженные чанки и блоки-сущности |
| лаг-спайк (0.4.0+) | время, длительность, кто занимал тик, горячие методы; у первых трёх спайков минуты — до 20 строк лога плагинов |
| журнал чата и команд (0.4.0+, только если включён в панели) | время, вид, ник, текст после маскировки, плагин-владелец команды, мир |

**Приватность.** UUID игрока превращается в `SHA-256(uuid_salt + uuid)`, а бэкенд дополнительно прогоняет этот хеш через HMAC со своим секретом. IP и инвентарь не собираются. Ники, чат и команды собираются только в журнале, который владелец сервера включает в панели (см. «Журнал чата и команд»). Объекты `Player`, `Entity`, `Location` и `Throwable` не хранятся: в буфер сразу попадает готовая строка.

Пример батча:

```json
{"batchId":"5b0e8c1a-3f2d-4a7b-9c11-2e4f6a8b9d00","sentAt":1793635210000,
 "plugin":{"version":"0.2.0","core":"leaf","mcVersion":"1.21.4"},
 "events":[
  {"type":"join","ts":1793635201234,"playerHash":"9f86d0…0a08","firstJoin":false,"world":"world"},
  {"type":"death","ts":1793635203456,"playerHash":"9f86d0…0a08","cause":"ENTITY_ATTACK","killerType":"ZOMBIE","world":"world"},
  {"type":"quit","ts":1793635207890,"playerHash":"9f86d0…0a08","sessionSec":6},
  {"type":"error","ts":1793635208000,"logger":"Minecraft","message":"Could not pass event PlayerJoinEvent to SomePlugin",
   "trace":"java.lang.NullPointerException: …\n\tat a.b.C.d(C.java:42)\n\t... 57 lines omitted ...\n\tat java.lang.Thread.run(Thread.java:833)"}
 ],
 "metrics":[{"ts":1793635205000,"tps":20.0,"mspt":11.9,"online":37,"entities":2850}]}
```

Всё, что не ASCII, экранируется как `\uXXXX`, поэтому длина тела в символах совпадает с длиной в байтах. Батч ограничен 60 KB при лимите бэкенда 64 KB.

## Журнал чата и команд

Появился в 0.4.0. Чат и команды включаются в панели по отдельности, по умолчанию оба выключены. Нужен, чтобы видеть, кто и что выполнил перед лаг-спайком.

- **Что пишется:** сообщения чата, команды игроков, команды консоли и RCON. Командные блоки не пишутся.
- **Что скрывается до отправки:**
  - команды со входом и паролями, например `/login`, `/register`, `/changepassword`, `/2fa`;
  - личные сообщения, например `/msg`, `/tell`, `/r`, `/mail`: остаётся только имя команды;
  - значение в `diag token`, токены и IPv4-адреса в любом тексте.
- **Как запретить на сервере:** `chat_log.allowed: false`. Панель тогда не сможет включить запись. Свои команды можно добавить в `chat_log.hidden_commands`.
- **Сколько хранится:** срок задаётся в панели, от 1 до 30 дней, по умолчанию 3. Журнал видит только владелец сервера.

Сообщите игрокам, что чат и команды записываются, например в правилах сервера.

**Совместимость.** Агент отправляет новые поля, только когда панель объявила их поддержку в ответе (`caps`). Со старой панелью он работает в прежнем формате: журнал и новые подробности спайков выключены, остальные данные приходят как раньше. Если панель отклонила батч с новыми полями, агент возвращается к прежнему формату.

## Диагностика по запросу поддержки

Если владелец сервера сам включит в обращении «Разрешить поддержке диагностику», поддержка MCDiag сможет попросить у агента:

| Команда | Что вернёт |
|---|---|
| `ping` | версия агента, аптайм, очередь и результат последней отправки |
| `status` | ядро, TPS 1/5/15, MSPT, онлайн, настройки агента — **без токена и соли** |
| `main_stack` | стек главного потока прямо сейчас (для зависаний) |
| `profile` | подробный профиль 10–120 с: сэмплы каждые 5 мс, доли плагинов и «горячие» методы |
| `plugins` | все плагины с версиями |
| `jvm` | версия Java, GC, аргументы запуска (значения `-D…` скрыты) |

Команды приходят в ответе панели на очередную отправку — входящих подключений к серверу нет. Все команды только читают: консольных команд, киков, перезапуска и изменения настроек среди них нет. Каждый запуск пишется в лог сервера: `Support diagnostics: <команда> done`. Набор команд зашит в агент, неизвестные игнорируются.

Если отправлять нечего, агент раз в 30 секунд шлёт пустой «пульс»: панель видит, что сервер на связи, а поддержка может передать команду.

## Профилировщик плагинов

Работает по тому же принципу, что Java-сэмплер [spark](https://spark.lucko.me/), но без интерфейса на сервере — графики, история и прогноз живут в панели MCDiag.

- **Главный поток.** Daemon-поток `MCDiag Profiler` в среднем раз в 50 мс смотрит на главный поток и записывает прошедшее время на плагин, чей код ближе всего к вершине стека. Если плагин вызвал API ядра, которое грузит чанк, время достаётся плагину, а не чанкам. Если плагина в стеке нет — части ядра: сущности, чанки, блоки, сеть, сохранение, прочее. Пока сервер ждёт следующего тика, стек не снимается вовсе. Интервал случайный: сэмплы с постоянным периодом 50 мс попадали бы в одну и ту же фазу тика.
- **Снимок стека.** На Java 19 и новее используется `Thread#getStackTrace`: приостанавливается только главный поток. На Java 17 единственный способ с ограничением глубины — `ThreadMXBean#getThreadInfo` (глубина 128), он останавливает всю JVM. Если снимки занимают больше 0,5% времени (внутри долгого тика 2%), агент сам снижает их частоту.
- **Чей класс.** Индекс пакетов строится по оглавлениям jar-файлов плагинов, классы не загружаются (поиск через загрузчик Bukkit писал бы в консоль «Loaded class … which is not a depend»). Пакет, который есть в нескольких jar, никому не приписывается — тогда сэмпл достаётся вызвавшему его плагину. Ответ для каждого класса кешируется.
- **Лаг-спайки.** События Paper `ServerTickStartEvent` / `ServerTickEndEvent` дают точную длительность тика. Если тик идёт дольше 50 мс, сэмплы снимаются каждые `interval_ms` (по умолчанию 20 мс). Тики длиннее `spike_threshold_ms` сохраняются вместе с долями плагинов по сэмплам именно этого тика.
- **Асинхронная нагрузка.** Раз в 5 секунд читается CPU-время потоков планировщика Paper (`Craft Scheduler Thread - N - <плагин>`), `ForkJoinPool` и потоков с именем плагина. Обычно плагин виден по имени потока, и JVM не останавливается. Стеки безымянных потоков снимаются одним запросом, это одна остановка JVM на все такие потоки.
- **Логи к спайкам.** Хендлер только запоминает ссылку на строку, маскировка выполняется в потоке профилировщика и только для строк, которые прикладываются к спайку. При `spike_logs: false` и со старой панелью строки не запоминаются.
- **Счётчики мира.** Сущности, чанки и блоки-сущности считаются в главном потоке обходом, поэтому за один запуск (5 с) обходится один мир. Чанки и блоки-сущности обновляются в 6 раз реже. С несколькими мирами цифры обновляются реже, но новый мир учитывается сразу.
- **Стоимость.** Реальные цифры на вашем сервере показывает `/diag status`: снимков стека в секунду, их доля времени и собственный CPU профилировщика.
- **Точность.** Это оценка по сэмплам: код, который работает реже интервала, может не попасть в срез. На здоровом сервере за минуту набирается 200–300 снимков в тике, поэтому погрешность доли плагина за минуту составляет около 2–3% от занятого времени. За час она в 8 раз меньше.

### Отправка и повторы

- Пока предыдущий запрос не завершён, новый не создаётся.
- Неудачный батч (сетевая ошибка, 5xx, 429) хранится как готовая строка (≤ 60 KB) и повторяется **с тем же `batchId`**. Бэкенд отбрасывает дубли по `batchId`, поэтому таймаут после успешной записи не удвоит данные. Буфер в это время копит новые события в пределах своего лимита, лишнее вытесняется.
- Задержка между повторами растёт экспоненциально, до 5 минут. На 429 выдерживается `Retry-After`.
- 400 / 413: батч отбрасывается. 401 / 403 (токен недействителен или подписка неактивна): батч отбрасывается, пауза 60 с. В лог пишется только смена состояния, токен — никогда.

### Бюджет памяти

| Что | Обычно | Худший случай |
|---|---|---|
| Буфер событий (500) | ~75 KB | ~3,5 MB (500 ошибок по ~7 KB) |
| Буфер метрик (60) | ~5 KB | ~5 KB |
| Срезы профилировщика (10) | ~2–3 KB | ~40 KB |
| Кеш «класс → плагин» | ~200 KB | ~5 MB (50 000 классов, затем сброс) |
| Неотправленный батч | 0 | 60 KB |
| StringBuilder батча (переиспользуется) | 8–16 KB | 60 KB на время сборки |

## Ограничения

- Перехватываются ошибки, записанные через `java.util.logging`: логгеры плагинов, `Could not pass event …`, ошибки команд. Ошибки ядра, которые пишутся только через Log4j, не видны: для этого нужен log4j-core, а он не входит в публичный API. Исключения в задачах планировщика Paper пишет с уровнем WARNING, поэтому они тоже не собираются.
- При выключении сервера неотправленный остаток (до одного интервала) теряется: в `onDisable` сетевые вызовы из основного потока запрещены.
- Folia не поддерживается.
- Строки лога у спайка берутся из `java.util.logging`. Строки ядра, которые пишутся только через Log4j, не видны.
- Кисти WorldEdit работают без команды при каждом клике, поэтому в журнале и причинах спайка они не видны.
- Профилировщик видит код, загруженный из jar-файла плагина. Библиотеки, которые Paper скачивает по `libraries:` из plugin.yml, лежат отдельно — их время достаётся плагину, который их вызвал.

## Сборка

Нужен JDK 17+.

```bash
./gradlew build
```

Jar появится в `build/libs/MCDiag-Agent.jar`. Тесты (`./gradlew test`) проверяют экранирование JSON, обрезку стектрейса, буфер и лимиты батча, атрибуцию стеков, срезы профилировщика и стоимость сэмпла. Тест сборки батча пишет пример тела в `build/sample-batch.json`.
